# 业务规则与操作铁律

这些是项目长期约定，**任何情况下不得违反**。

## 入库规则

1. **无零件号一律拒绝入库**——不管价格多完整。这是用户明确定的硬规则。
2. **无价格的行跳过**（不建零件、不建报价）。
3. **品牌必填且必须存在于 brands 表**，英文全大写。若文件里品牌列为空，必须向用户确认后再补，**不得自行猜测填入**（即使迹象明显也先问）。
4. **质量等级按原文入库，严禁归一化**。库里有 100+ 种写法属正常。
5. **同零件 + 同供应商 + 同质量出现多个价格 → 取高价**。
6. 中英文名称：中文名填充率 98%+，新件应自动生成中文名填入，不留空。

## 质量等级不可归一化（重要）

「质量等级」承载两级信息：第一级是原厂/副厂广义分类，第二级是细分来源。
东亚、东康（东风康明斯）、重康（重庆康明斯）、美康（美国进口）、博世、唐纳森、德尔福、CTP、FKM、PERKINS 等都是**有意义的细分标识**，不得清洗成「原厂」或「副厂」。

常见值（报价条数）：副厂 3090、原厂 1801、Genuine CAT 403、Aftermarket 71、美康 57、东亚 49、再制造 48、Genuine 42、优质 36、博世 23。

⚠️ 已知陷阱：同一零件两家报价价差可达 10 倍以上（如 Perkins 282/296：佛山帕金斯 207.13 vs 吕光辉 15），但质量字段都写「原厂」。报价给客户前必须向用户提示这一差异，让用户判断档次。

## 供应商名统一：只改名，不合并（重要）

- 用户要求「供应商名统一」时，默认是**更正名称拼写**（`UPDATE suppliers SET name=? WHERE id=?`），**不是合并记录**。
- 禁止：迁移报价到另一 supplier_id、删除源供应商、因冲突取高价删低价。
- 报价记录、价格、来源行号一律原样保留。
- 若改名会导致两个 supplier_id 同名（UNIQUE 冲突），必须先向用户说明并确认。
- `scripts/merge_suppliers.py` 做的是**合并迁移**，与改名是两回事，使用前必须确认用户意图。
- 用户（2026-09-30）决定：供应商名**保持现状不统一**，不同写法他自己都认得是谁。今后发现疑似重复供应商名 → **只提醒、不动手**。

## 备份与同步

- **只在写库后同步云端**（导入、单件增删改、拆分/合并）。纯查询任务结束后**不得**自动跑同步。
- 同步方式：整文件复制（cp），云端始终是一份可直接打开使用的完整库。
- **不要用 rsync --delete**：该操作会被权限规则拦截导致同步失败。用 `scripts/backup_to_cloud.py`。
- 任何批量写库前先打快照：`cp supplier_db.sqlite supplier_db.sqlite.bak_<动作>_<时间戳>`，或 `incremental_import.py real ... --backup`。
- 大操作后必跑 `PRAGMA integrity_check` + 抽查关键件，再同步云端。
- 回滚：用快照整文件覆盖即可。

## 已知历史坑

1. **合并脏件号**：早期导入把同格双号粘成一个号，如 `CH11304T436534`、`3T63526N9294`、`U5LL0021U5LL0015`。处理规则=拆成主件号 + 通用号（主件保留报价，另一号挂入 part_alternates）。发现即按此处理，并先备份。
2. **代替件列误填公式**：模板第 12/13/14 列只能填真实代替件号。曾因填了价差公式（如 2484.3）导致 18 条垃圾代替件入库。`incremental_import.py` 已加 `clean_alt()` 防护（拒绝带小数的数值、超长纯数字）。导入后仍应抽查代替件增量是否异常。
3. **dry-run 会写库**：`incremental_import.py` 早期版本 dry-run 与 real 共用写库逻辑，已修复（现在 dry-run 只预览）。仍建议先 dry-run 再 real。
4. **脚本计数虚高**：同一个零件号写多行时，`INSERT OR IGNORE` 复用同一零件，real 输出的「新增零件 +N」会大于实际增量，以 COUNT 核验为准。
5. **沙箱重跑**：含 UPDATE 的命令可能被重跑，第二次 rowcount 显示 0 或撞 UNIQUE 报错——以最终数据核验为准，不要据此判断失败。
6. **脚本只更新报价不更新机型**：对已存在零件追加报价时，机型字段不会被更新，需手动 `UPDATE parts SET models=? WHERE id=?`（追加而非覆盖原值）。
7. **报价单性质界定**：拿到一份表格先判断「单价」是供应商给我们的采购成本价，还是我们报给客户的对外售价。**对外售价绝不能入库**，会污染成本库。存疑必须问用户。
